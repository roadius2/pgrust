## 3. Facts established while planning (2026-10-06/07; all in the plan's header)

- **Sparse kernel codegen.** Disassembly of both C builds, the macOS clang arm64 reference and Docker's gcc arm64 `vector.so`:
  - **L2 merge:** both emit `fsub` + `fmadd` per scalar step. 12 of 12 random pairs equal a fused computation on arm64, and an unfused one on the amd64 image under emulation.
  - **L1 merge:** `fabd` + `fadd`, nothing to fuse.
  - **Long tails:** vectorized, differently by each compiler.
- **Scale.** A 10,000-row seeded vector build is byte-identical between `pgvec-seeded` and current pgrust, even though C's graph spans several 1 MB blocks. Current pgrust stops iterative scans on it where C does.
- **Harness gap the plan fixes.** `sqldiff.sh ref` compares stock C with the seeded build, which prints `memory:` INFO lines for every HNSW build and scan. Task 2 adds a filter.
- **SQL can't reach the support functions.** `SELECT hnsw_*_support(NULL)` fails in C with `function ... does not exist`.
